# Тихая форма

Одностраничный демонстрационный сайт записи к мастеру маникюра. React/Vite/TypeScript/SCSS Modules, Django 5.2, Poetry и SQLite. Название, мастер, адрес и цены вымышлены.

## Обычный запуск

Два терминала, без дополнительных сервисов:

```powershell
cd backend
poetry run python manage.py runserver
```

```powershell
cd frontend
npm run dev
```

Сайт: http://127.0.0.1:5174/ . Админка: http://127.0.0.1:8018/admin/ . Для проекта выбраны отдельные порты, чтобы не мешать уже запущенным локальным проектам.

Логин и случайный локальный пароль: `backend/.local/admin-login.txt`. Файл, секрет Django и база исключены из Git. Права Django Admin и CSRF действуют и в тестовом режиме.

## Первичная установка на другом компьютере

Нужны Python 3.12+, Poetry и Node.js 22.12+.

```powershell
cd backend
poetry install
poetry run python manage.py migrate
poetry run python manage.py seed_demo
cd ../frontend
npm ci
npm run build
```

Команда seed_demo сохраняет существующие настройки и создаёт недостающие материалы. Изображения уже входят в репозиторий. Локальная база подготавливается миграциями и seed, а не распространяется вместе с учётными записями.

## Управление

- «Настройки студии»: тексты, мастер, адрес, шаг старта, буфер, горизонт, SEO и интеграции.
- «Рабочие периоды»: часы по дням недели, в том числе несколько периодов с перерывом. День без периода считается выходным.
- «Выходные и перерывы»: исключения на конкретную дату целиком или по времени.
- «Услуги и стоимость», «Форма, длина, цвет и покрытие», «Галерея вдохновения»: содержание публичного сайта.
- «Записи клиентов»: поиск, фильтры, перенос на свободное время, отмена и освобождение интервала.
- «Журнал интеграций»: имитации без внешних отправок.

Отмена посетителем — через «Моя запись» и выданный код. Код не сохраняется автоматически, его надо скопировать. Одновременные и пересекающиеся бронирования проверяются внутри транзакции. Время — московское.

## Приватность демонстрации

`makeBooking` не принимает настоящее имя, телефон или файлы. После браузерной проверки форма очищается; на сервер отправляются случайные вымышленные контакты. Сервер не доверяет этим полям и генерирует собственные фиктивные значения. В базе нет полей для настоящих контактов. Файлы существуют только в памяти браузера до закрытия диалога; сервер получает число референсов. Журнал интеграций не содержит контактов.

Внешних счётчиков, iframe-карт, CAPTCHA, почтовых и иных отправок нет. Сайт использует только технические cookie Django для CSRF, админской сессии и ограничения частоты записей. Встроенный сервер и будущая инфраструктура хостинга могут иметь собственные технические логи: их политику настраивают при размещении.

Локальный тестовый режим доступен через админку только при `DJANGO_ENV=local` (по умолчанию). В production он блокируется и не даёт обходить авторизацию. Отключение режима показывает недостающую конфигурацию и запрет внешних интеграций в демонстрации. Настоящие Яндекс Метрика и Карты требуют отдельного коммерческого режима с соответствующими уведомлениями посетителей; автоматически их включить в этой версии нельзя.

## Сборка и SEO

```powershell
cd frontend
npm run build
```

После сборки Django также отдаёт сайт целиком по http://127.0.0.1:8018/ с серверным начальным HTML и SEO из базы. В dev Vite подгружает SEO из API. `robots.txt` и `sitemap.xml` выдаёт Django. Canonical и разрешение индексации меняются в админке. Демонстрация по умолчанию `noindex` и `Disallow: /`.

Production требует отдельной настройки HTTPS, хоста и инфраструктурных секретов: `DJANGO_ENV=production`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`. Статические и медиафайлы в production обслуживает веб-сервер; выполнить `collectstatic`. Публичный деплой в рамках этой задачи не выполняется.
